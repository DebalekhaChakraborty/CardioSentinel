**This receipt deliberately names no digest.** The task that produced it was
scoped to define what an authoritative environment is, not to select one, and a
receipt carrying a plausible-looking digest is exactly the artifact a later
reader — or a later piece of code — could mistake for authority. A dash here is
the honest state; a fabricated digest would not be.

When an environment is built, it is verified against this mechanism and recorded
in a **V2 receipt** naming its real `environment_id` and `environment_sha256`.
This V1 receipt is not edited to add them.

### Runtime checks exercised

Against synthetic records only:

- canonical form is field-ordered, newline-terminated, whitespace-refusing;
- every digest-bearing field changes the digest;
- excluded fields — `creation_timestamp`, `owner_provenance_identity` — **do
  not**;
- dependency mapping order does not change the digest;
- a modified digest fails;
- a missing immutable artifact fails;
- every blank field fails;
- five forms of mutable local state fail: home paths, `localhost`,
  `current-machine`, `developer-laptop`, `unknown`;
- Python, OS and dependency-digest runtime mismatches each fail;
- preflight refuses without an environment authority;
- no bypass parameter exists;
- `AUTHORIZED` is unreachable from the package;
- **no production path derives authority from hostname, username, home
  directory or a filesystem scan** — proven by AST, not text scan.
