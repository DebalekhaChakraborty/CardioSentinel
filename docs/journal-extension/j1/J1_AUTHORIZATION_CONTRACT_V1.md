## 2. Environment authority

| Field | Rule |
|---|---|
| `environment_authority_id` | must reference an **existing qualified** Environment Authority Record |
| `environment_sha256` | 64 lowercase hex, the digest of that record's canonical serialization |

**Forbidden.** The digest **cannot be generated by the execution runtime**,

naming a home path, `localhost`, `current-machine`, `developer-laptop`,
`workstation`, `unbound`, `unknown`, `TBD` or `n/a` is refused with the reason
stated.

**Current state: no environment has been submitted.** The mechanism is qualified;
no record exists to name. This contract therefore names none — a plausible-looking
digest here is exactly the artifact a later reader, or a later piece of code,
would mistake for authority.

## 4. Attempt budget

A mandatory integer.

| Value | Meaning |
|---|---|
| **absent** | **refusal** — and it refuses in its own words, before the generic missing-field sweep |
| **negative** | refusal |
| **non-integer** | refusal — including `True`, `"1"` and `1.0` |
| **zero** | **an explicit human decision**: authorized, and permitted no attempts |
| **≥ 1** | the number of attempts the signer authorized |

**A missing budget is never interpreted as one attempt.**

**Why zero is recordable here but not runnable.** Zero and absent are different
states, and collapsing them is the failure this programme has guarded against
since V1. A contract that refused to record zero would leave a person no way to
write down the decision they actually made. So the contract records zero and
reports `permits_attempt = False`; **preflight's own gate still refuses to start
a run on a budget below one.** Those are different questions asked at different
times.

**No contract, of any budget, ever reports `permits_attempt = True`.** A contract
is not a permission.

## 5. Provenance sink

| Field | Rule |
|---|---|
| `provenance_sink_id` | names the sink |
| `provenance_sink_destination` | an addressed, immutable destination |

**Rules.** The **runtime cannot choose the sink** — it is supplied before
execution. A destination must carry a URI scheme; the `file`, `http` and `ftp`
schemes are refused, as are bare absolute paths, relative paths and any value
naming mutable local state.

**A local filesystem path is insufficient authority.** It names a location on one
machine, not a durable destination at which the record can be found later.

## 6. Decision authority

Four outcomes, each declared by a **named person or body**:

| Field | Declares |
|---|---|
| `scientific_success_authority` | scientific success |
| `scientific_failure_authority` | scientific failure |
| `inconclusive_outcome_authority` | an inconclusive outcome |
| `apparatus_failure_authority` | apparatus failure |
| `apparatus_after_visibility_authority` | apparatus questions after results are visible |

**The runtime must never decide a publication outcome.** A field naming

the decider is refused.

Matching is by **whole word**, not substring: a contract that refuses a real
reviewer's name because it contains `self` inside `herself` is broken, not
stricter.

## 7. Authorization state machine

```text
ABSENT  ──►  DRAFT  ──►  AUTHORIZED
```

| State | Reached by |
|---|---|
| `ABSENT` | the repository's current and ordinary state |
| `DRAFT` | a complete, admissible contract that nobody has signed |
| `AUTHORIZED` | **a human act naming the contract** |

**Rules, each asserted by test rather than by intention:**

- `verify_contract` returns `DRAFT` and never `AUTHORIZED`;
- **there is no transition function to `AUTHORIZED` anywhere in the package** —
  proven by an AST walk over every J1 module, not a text scan, since this
  document and that enum necessarily name the state they forbid reaching;
- `J1AuthorizationContract` exposes no `authorize`, `sign`, `promote`, `approve`
  or `grant`;
- **no `DEV_MODE`, `FORCE` or `SKIP` bypass** — `verify_contract` has no
  `dev_mode`, `force`, `skip_checks`, `state` or `authorized` parameter;
- a field the contract does not define is refused outright, so a bypass cannot
  be smuggled in as unrecognised data.

## 8. Negative capability

| Proven | How |
|---|---|
| Execution cannot start without authorization | preflight refuses at the authorization stage, before git, environment, capability or budget |
| A draft contract is not an execution authorization | handing one to `verify_authorization` fails rather than quietly satisfying it |
| Authorization cannot be synthesized by the runtime | AST walk: no package path reads `AuthorizationState.AUTHORIZED`; the contract module calls no `gethostname`, `getlogin`, `getuser`, `expanduser` or filesystem walk |
| The attempt budget cannot default | absence refuses in its own words; `True`, `"1"`, `1.0`, `None` and negatives all refuse |
| The environment cannot be guessed | local, machine-derived and placeholder values refused with the reason stated |
| TRAIN authority cannot expand | `allowed_partition` must be `V1_TRAIN_ONLY`; forbidden partitions and discovery language refused **in every field** |

### The contract and the execution schema cannot drift

`authorization.py` is the narrower schema preflight checks in the seconds before
a claim. This contract is the superset a person populates days earlier, and it
includes questions preflight has no opinion about — who may declare a result
inconclusive, which commit's collaborators were reviewed.

`EXECUTION_SCHEMA_COVERAGE` maps **every** `authorization.REQUIRED_FIELDS` entry
to the contract field carrying it, and a test asserts the map is total in both
directions. A new execution field with no contract home is a test failure.
