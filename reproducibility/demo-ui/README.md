# CardioSentinel Demo UI

**This interface adds no inference, training, model-selection, threshold-selection
or scientific logic.**

It renders a snapshot generated by the existing CardioSentinel replay runtime.
The runtime remains authoritative. The UI exists to make the contracted
demonstration easier to inspect and record.

Every scientific value on screen is read from an `EdgeObservation`, an
`AlertEvent`, an `EvidenceRecord`, or the existing agent output. The browser
implements no second detector, no threshold, and no state machine.

---

## 1. Generate the snapshot

From the repository root, on the frozen scientific interpreter:

```bash
python reproducibility/demo-ui/export_snapshot.py
```

The exporter calls the existing `replay_record()` with the canonical demo
arguments — record `s20201`, subject `ltstdb:s2020`, channel 0, 2400 simulated
seconds, reading the committed demo bundle — and then **checks the result
against the contracted demonstration before writing anything.**

If any contracted value differs, it prints a mismatch report and **writes no
snapshot**. A presentation layer that silently renders different numbers than
the runtime asserted is worse than no presentation layer.

It writes `reproducibility/demo-ui/demo_snapshot.json`.

### Optional: exercise the guarded generative path

```bash
python reproducibility/demo-ui/export_snapshot.py --with-local-models \
  --hf-cache /path/to/huggingface/hub
```

This runs each **locally cached** open-weight model — `Qwen/Qwen3-1.7B` and
`Qwen/Qwen3-4B-Instruct-2507`, pinned to the immutable revisions the evaluation
record fixes — through the **same** `PatientExplanationAgent` the runtime uses,
and records what the guard did with each generation.

**It downloads nothing.** A missing or incomplete cache raises
`ProviderUnavailable` and is recorded as unavailable rather than silently
skipped. `HF_HUB_OFFLINE=1` is set for the run.

What is recorded per model is the runtime's own decision — `explanation_mode`,
`provider`, `fallback_reason`, `claim_violations`, the immutable provider
identity and the generation latency. A refused generation arrives as
`DETERMINISTIC` with the refusal reason attached, and **that is stored as-is**:
the refusal is the result, not an error to smooth away.

**The refused generation itself is not retained** — the runtime keeps the reason,
not the text it rejected — so the dashboard shows what was *delivered* and why,
and never reconstructs what was refused.

One evidence context, one run per model. That demonstrates the mechanism, not a
rate: no failure rate and no scaling law is claimed.

## 2. Serve the repository locally

From the repository root:

```bash
python -m http.server 8081 --bind 0.0.0.0
```

The standard-library server is sufficient; there is no backend.

## 3. Open the dashboard

```
http://localhost:8081/reproducibility/demo-ui/
```

If the browser is on a different machine from the repository, forward the port
over SSH rather than exposing it:

```bash
ssh -L 8081:localhost:8081 <user>@<vm>
```

Then open the same `localhost:8081` URL on the local machine.

Once `demo_snapshot.json` exists the page works **offline**: no CDN, no external
script, stylesheet or font, no analytics, no remote model call. The only request
it makes is `fetch("./demo_snapshot.json")`, plus the tracked figure at
`../../docs/paper/figures/F5_guarded_generation.png`, which is rendered in place
and never copied or regenerated.

## What the display waveform is, and is not

The ECG shown is the **real** `s20201` channel-0 signal, read through the
repository's existing signal path.

It is **display-decimated from 250 Hz to 25 Hz by fixed-stride selection** — no
filter, no resampling kernel, no interpolation. Every displayed sample is a
source sample, rounded for transport only.

**The decimated series is never an inference input.** The runtime consumed the
250 Hz signal; the snapshot records this explicitly:

```json
"source_sampling_frequency_hz": 250,
"display_sampling_frequency_hz": 25,
"display_waveform_is_inference_input": false,
"display_waveform_purpose": "visualization_only"
```

## What this dashboard is not

- **Not a clinical dashboard, and not a diagnostic or medical-device interface.**
  The alert is a research output. No clinical utility is claimed.
- **Not edge-hardware validation.** This is a stored-record replay on a general
  purpose machine. There is no sensor and no acquisition path.
- **Not a live model call.** The GUARDED AI tab renders a frozen
  explanation-evaluation result. No language model is invoked, locally or
  remotely.

The `wall_seconds` and `real_time_factor` fields describe the replay execution
that produced the snapshot on that host. They are labelled *"Snapshot generation
on this host"* and are unrelated to browser playback speed, which is labelled
**visualization playback**.

## Why `demo_snapshot.json` is not committed

It is a **derived** file — regenerable at any time from the runtime and the
committed demo bundle — so it is listed in this directory's `.gitignore`. Only
the generated snapshot is ignored; nothing else here is.

Committing it would add a large artifact whose authority is the runtime's, not
its own, and would create a second place for a scientific value to drift.

## Dependencies

None beyond the existing CardioSentinel package and the Python standard library.
The page is plain HTML, CSS and vanilla JavaScript with Canvas — no framework,
no npm, no bundler, no charting library.
